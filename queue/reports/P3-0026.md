# P3-0026 — Book notes, skupina VI tehnički, paket _a

## Scope

Wrote `quiz/build/notes_book_s6_tehnicki_a.json`: one teaching note per id in
`quiz/build/work/packet_book_s6_tehnicki_a.json` (30 ids, `bk-teh-6-01` through `bk-teh-6-59`,
odd numbers only — the `_a` half of skupina VI's technical exam). Same `{note, formula?,
cite}` shape as the sibling `notes_book_s5_tehnicki_a.json`. No `links` key — matches the
established convention that `link_check.py`/`check_notes.py` only glob `notes_zzz_expanded_*`.
`packet_book_s6_tehnicki_a.json` (also listed in `files:`) was read only, not edited.

## Method

Dumped RK printed pages 344-355 (the whole SKUPINA VI exam paper plus both halves of its
answer-key table) with `booktool.py page` for text, then rendered the same PDF pages
(pdf index 338-349) to PNG at matrix 3x-8x and viewed every one, because — as the brief and
every earlier P3 book-notes item warn — this PDF's line art is near-invisible to
`get_images()`/`get_drawings()` and the OCR text layer mangles circuit labels, Greek letters,
and multi-column tables. Every one of the 30 questions' options was checked word-for-word
against the rendered image, not the packet's OCR'd `question`/`options` text or its
`current_cite`/`current_explanation`.

**Extra step this item, per the caller's brief:** every one of the 30 HRS answer *letters* in
the packet was additionally cross-checked against the actual "ODGOVORI NA PITANJA" table
(tiskana str. 354-355, rendered at 8x, rows 1-60, column "SkupinaVI") — not just trusted from
`current_cite`. All 30 letters match the table exactly (my first low-res read of row 21
misread B as D; a second render at 8x zoom corrected it — recorded here so the mistake isn't
silently repeated). Supporting theory citations were pulled by locating the matching RK
chapter via `booktool.py toc`/`find` and reading the actual page text, e.g. p.72 for the
transformer-ratio formula, p.135 for the image-frequency definition, p.159 for the
quarter-wave transformer formula, p.199 for the three interference paths, p.201 for the
144 MHz→UHF-TV high-pass-filter example (the book gives that exact scenario).

  coil 1mH/10Ω+90Ω, 500Ω); U1=10V confirmed by rendering and by simple series-divider math on
  the R1/R2 branch (the other two branches are red herrings — they share the same terminal
  voltage but don't affect the internal split of the R1/R2 branch).
- **bk-teh-6-05**: E/H polarization diagram, E vertical → vertical polarization.
- **bk-teh-6-09**: series LC circuit with UL, UC labeled — see the option-scramble defect below.
- **bk-teh-6-11**: coaxial λ/4 stub schematic (Z0=50Ω terminated in 75Ω).
- **bk-teh-6-13**: three series capacitors C1=C2=C3=66pF.
- **bk-teh-6-19**: antenna sketch (grounded vertical wire, coil, variable capacitor) — a
  Marconi antenna, not a Hertz dipole.
- **bk-teh-6-45**: oscilloscope sine-wave oscillogram.

**Important nuance found this item:** `quiz/build/figs_book_index.json` (a separate,

## Defects that change what the answer text actually says (not just the letter)

- **bk-teh-6-09**: packet's options (c) and (d) are swapped relative to the real page. Real
  page: (a)0° (b)90° (c)270° (d)180°. Packet: (c)="180%", (d)="270\" o". The packet's
  `answer` letter "d" is still the *correct letter* (confirmed both by the answer table and by
  phase physics — UL and UC in a series L-C branch are always 180° apart), but the *text* the
  packet attaches to that letter belongs to the real (c), not (d). Real (d) is 180°, which is
  what HRS actually marks correct.
- **bk-teh-6-51**: this question is a two-column table (impedancija / gušenje) per option; the
  packet kept only the impedance column and dropped attenuation entirely. Real options: (a) 75
  oma/3 dB, (b) 3 oma/75 dB, (c) 25 oma/60 dB, (d) 50 oma/−75 dB. Packet has only
  "75 oma"/"3 oma"/"25 oma"/"50 oma".
- **bk-teh-6-55**: packet's `answer_text` for (c) is "zračenjem, indukcijom" — the real page
  reads "zračenjem, indukcijom i vođenjem" (three interference paths, not two; "i vođenjem"
  was dropped). The book's own EMC section (p.199) states this three-way list almost verbatim,
  which is how the omission surfaced.

All three are written up with the full, page-verified text in the note; none of the packet's
`answer` letters were touched (rule 1) — only the prose describing what those letters mean.

## Two questions with weak or no supplementary book citation

- **bk-teh-6-29** (2nd IF of a double-superhet stays constant): the book shows the
  double-conversion block diagram (p.129) but never states the "1st IF varies / 2nd IF fixed"
  rule in words — noted as inferred from receiver architecture, not quoted.
- **bk-teh-6-25** (EME needs VHF+): no explicit "Mjesec"/EME sentence found anywhere in RK;
  the note draws on the general VHF/UHF-passes-through-ionosphere rule (p.167) and says so.
- **bk-teh-6-43** (place-value of digit "7" in "7,0876 MHz"): flagged as ambiguous — the digit
  7 appears twice (millions place and, inside the fractional MHz digits, the thousands place);
  HRS's answer (b, "seven thousand Hz") only makes sense for the second occurrence. No book
  sentence covers this reading convention; said so rather than inventing one.
- **bk-teh-6-59** (first aid at electric shock): RK's safety chapter (10.1) covers physiological
  effects and grounding precautions but no first-aid procedure; cited the exam page only.

## Finding beyond this item's scope — book notes are not wired into the built quiz

`rebuild.py`'s "attach explanations" loop (around line 110-129) builds its `byid` lookup only
from `hrs` (the 456 official HRS-key questions) and never from `extra` (the 720 book
questions, which is where every `bk-*` id — including all 30 written here — actually lives in
`questions.json["questions_extra"]`). Concretely: `byid = {q["id"]: q for q in hrs}`, then the
notes-attach loop does `q = byid.get(qid)` and silently `continue`s to an `unknown` list when
the id isn't found there. Running `rebuild.py` prints `! notes for unknown ids: [...]` with
every single `bk-*` id from every skupina 1-6 in the corpus — not just skupina VI — so **this
is a pre-existing gap affecting this entire book-notes series (P3-0006 through P3-0026), not
something introduced by this item.** The book packets' own `explanation`/`note` field is never
populated, `doc["_meta"]["explained"]` only counts `hrs`, and `check_notes.py`/`link_check.py`
never see these files either (wrong glob, by design). None of that blocks `rebuild.py`
(it's an informational print, not an abort), so `1176 questions, all answerable` still holds —
but readers of the built `quiz.html` currently see no explanation text on any book-sourced
question. Left alone (outside this item's `files:`, and a `rebuild.py` change is too
consequential to make inside a single-file notes item) — worth its own follow-up item to wire
`extra` into the explanation-attach loop (or build a parallel `byid_extra`) so five items'
worth of notes (s1-s6, ~180 notes once this series finishes) actually reach the quiz.
