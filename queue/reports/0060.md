# P2-0060: Add question-feedback reporting to the quiz

## What was built

**1. "Report a problem" control on every question (`quiz/build/build_quiz.py`, not
`quiz/quiz.html`).**

`quiz/quiz.html` is a generated artefact — `quiz/build/rebuild.py` calls `build_quiz.py`,
which holds the entire page (CSS, HTML, JS) as one Python triple-quoted string and writes it
out with the question payload substituted in. It is also gitignored (`.gitignore`: "Keeping
generated files out of git is what makes parallel branches mergeable"), so `git add
quiz/quiz.html` is a no-op regardless. The item's `files:` list names `quiz/quiz.html`, but
the actual, git-tracked source for everything below is `quiz/build/build_quiz.py`; I edited
that and regenerated `quiz/quiz.html` locally to verify. Flagging this since it's a file
outside the literal `files:` list, even though it's the only file that could carry this
change.

Added, inside the existing `#quiz` screen's `.qcard` nav row:

- A `#reportBtn` button ("Prijavi problem") next to Prev/Next.
- A `#reportMask`/`.report-box` modal — styled as a variant of the existing `#confirmMask`
  dialog (same classes, new `.report-*` rules for the form controls), not a second dialog
  system. Contains a reason `<select>` (5 options: netočan odgovor / loša-pogrešna citacija /
  tipfeler-nejasan tekst / nedostaje-pogrešna slika / ostalo), a free-text `<textarea>`, and
  an `<a id="reportGo" target="_blank" rel="noopener noreferrer">` that opens the prefilled
  GitHub issue.
- `reportUrl()` builds `https://github.com/<REPO>/issues/new?title=...&body=...
  &labels=quiz-feedback`, with the question id, the current correct answer (`q.o[q.a]`), its
  citation(s) (`q.cs`/`q.c`, same fields `render()`'s own citation block reads), the chosen
  reason, and the free text.
- `openReport()`/modal wiring follows the exact pattern of the existing `askConfirm()`:
  Escape closes, backdrop click closes, focus is stored and restored. The `reportGo` anchor's
  `href` is computed inside its own `onclick`, same tick the browser reads it for navigation,
  since reason/note can change after the dialog opens.

**Why a real `<a target="_blank">` and not `window.open()`:** the file already documents
(comment above `askConfirm()`) that `window.confirm()`/`alert()`/`prompt()` are silent
no-ops in the sandboxed iframe this page runs in on claude.ai (P1-0038). `window.open()` is
gated by the same `allow-popups` sandbox flag. The existing citation links in `render()`
already use a real anchor click for external navigation and are known to work there, so
`reportGo` follows that exact precedent instead of risking the same silent-no-op class of
bug. Also no `<form>`/submit, per the existing comment by `doLookup()` about
`allow-forms` — the dialog is plain buttons/inputs, same as the rest of the page.

**2. `owner/repo`, read from git at build time, not hardcoded.**

`build_quiz.py` gained `repo_slug()`: runs `git remote get-url origin` (cwd=`quiz/`'s
parent), regexes out `owner/repo` from either the SSH or HTTPS remote-URL form, and returns
`""` if there's no `origin` or the URL doesn't parse to `github.com`. The result is baked
into the page as `const REPO = __REPO__;` (via `json.dumps(REPO)`, same placeholder-replace
mechanism the question payload already uses for `__PAYLOAD__`). The JS then does
`REPORT_ENABLED = !!REPO` and **hides `#reportBtn` entirely** when `REPO` is empty, rather
than shipping a button that links to a broken URL.

This matters concretely: **this repo currently has no `origin` remote at all** (confirmed via
`git remote -v` — empty, same fact `PUBLISHING.md` and `queue/done/P2-0058-*.md` already
record: a remote is Glaukon's call, not something to add here). I verified both branches of
`repo_slug()`:
- No remote → `rebuild.py` prints `repo=(none — report button hidden)`, `quiz.html` contains
  `const REPO = "";`, and `#reportBtn` gets `.hidden` added at load.
- I temporarily ran `git remote add origin git@github.com:GlaukonAriston/ham-radio-license.git`,
  reran `build_quiz.py` alone (not the full rebuild, to avoid re-parsing PDFs), and confirmed
  `const REPO = "GlaukonAriston/ham-radio-license";` and a live
  `https://github.com/...` issue link were baked in correctly for both the SSH and (checked
  separately, via a standalone regex test, not by mutating the repo) HTTPS remote-URL forms.
  Then ran `git remote remove origin` to restore the original no-remote state before touching
  anything else, and reran `build_quiz.py` once more to confirm it reverts to `REPO = ""`.

**3. `queue/from_issues.py` (new file).**

Runs `gh issue list --label quiz-feedback --state open --json number,title,body`, and for
each open issue: calls `queue/new.py P2 "<issue title>"` (so numbering stays unique across
`todo/`+`done/`, per `new.py`'s own docstring — never writes into `queue/todo/` directly),
then rewrites the generated template's `cluster:` to `quiz-feedback`, its `files:` to a
pointer ("identify from the question id in Why, below — `quiz/build/notes_*.json` is the
usual answer" — a real path can't be derived automatically without parsing the issue body for
a question id and mapping it to the right notes file, which is exactly the judgement call the
resulting worker is for), and its **Why** section to the issue body verbatim. Then closes the
issue with `gh issue close <n> --comment "Triaged into <path>."`.

No CI/Action anywhere — this only ever runs locally, invoked by `/drain`.

**4. `.claude/commands/drain.md`: `python queue/from_issues.py`** added to "Setup, once per
drain", right after the `git switch queue-drain` line and before the `.inflight` recovery
table, with a short paragraph explaining what it does and that `gh` must already be
authenticated (no login flow added, per the item).

**5. `QUEUE.md`:** new "## Issues become items" section (between "Adding an item" and "Rules
that outrank anything an item says") documenting the same mechanism for a human reader, and
pointing at `PUBLISHING.md` for why this has to stay local/`/drain`-driven rather than a
GitHub Action.
