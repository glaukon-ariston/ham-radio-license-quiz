# P2-0042 — Transcribe bk-teh-2-03 as a figure-options question

## What was wrong

`bk-teh-2-03` (SKUPINA II, question 3; page 293 = PDF index 292, printed 298) is a
`Koja od skica predstavlja filtar...` question whose real answer choices are four
labelled frequency-response sketches `a)`-`d)` printed under the stem, not text. The
coordinate parser doesn't see them (this book has no vector art — `get_images()` returns
1 for the whole page, `get_drawings()` returns 0 — it's a raster scan with an OCR text
layer laid over it), so when it scanned forward for the next "real" option text it
crossed the page boundary and grabbed question 4's stem ("Sklop na slici je:") and
question 4's own four text options (`detektor ovojnice` / `ratio detektor` / `AM –
detektor` / `punovalni ispravljač`, verified still correctly attached to `bk-teh-2-04`
only — see below). This was diagnosed and explicitly left unfixed by a prior worker
(P2-0033, see its report's "Two things NOT done" section) because fixing it needs
`figure_is_options: true`, which that item's own "Avoid" line forbade.

## What I did

1. Rendered PDF page index 292 (printed 298) at 200dpi via pymupdf and read the real
   stem and the four sketches by eye: `a)` a bandpass/peak curve, `b)` a rising-shelf
   (high-pass-like) curve, `c)` a notch/valley curve, `d)` a low-pass shelf that's flat
   then rolls off after "3 kHz" — all four axes labelled "3 kHz" on the x-axis.
2. Confirmed via `page.get_text("blocks")` that question 3's real stem block
   ("Koja od skica predstavlja filtar, koji je prikladan da slijedi iza mikrofona sa
   ciljem ograničenja frekvencijskog pojasa:") ends at y=428.44 on page index 292, and
   that question 4's stem ("Sklop na slici je:", y=76.6) and its options
   (y=254.2-282.3, "detektor ovojnice" etc.) are on the *next* PDF page (index 293,
   printed 299) — two physically separate pages, confirming the parser's cross-page
   stitching bug and that `bk-teh-2-04`'s real content was never at risk from my edit
   (I didn't touch its override entry; diff confirms).
3. Added a `bk-teh-2-03` entry to `book_overrides.json`, same shape as the existing
   `bk-teh-2-20`/`bk-teh-2-46` `figure-options` overrides: `figure_is_options: true`,
   the real stem transcribed from the rendered page, options `{"a":"a)","b":"b)",
   "c":"c)","d":"d)"}` (picture labels, not text), and a crop window `figure: [428, 655]`
   — hand-picked by rendering test crops (428→700, then tightened to 428→655) until all
   four sketches + "3 kHz" labels were fully inside with no clipping and no dead
   whitespace.
4. Did **not** set or touch `answer` — it comes from `book_keys.json` purely
   positionally (row "3", column "II" of the `tehnicki` table = `D`), independent of
   option text, and was already `d` before my change (the corrupted entry coincidentally
   inherited the same letter). Verified this stays `d` in the final
   `quiz/questions.json` after rebuild, sourced as `"answer_source": "book-key-table"`.
