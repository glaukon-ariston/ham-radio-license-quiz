# P2-0032 — Restore book stem figures: skupina I

## Scope confirmed

"SKUPINA I — tehnički (tiskane str. 288–295)" = PDF pages 283–290 (this book's printed
page = PDF page + 5, per `book_overrides.json`'s own `_doc`), i.e. every `bk-teh-1-*`
question. Cross-checked two ways: `book_parsed2.json`'s `skupina` field (1 = Skupina I)
and the printed-page arithmetic agree. `fig_audit.py`'s suspect table for that page range,
plus `bk-teh-1-12` (already an override for a different reason, as the item said), gives
exactly 9 ids — matching the item's own count:

`bk-teh-1-04, bk-teh-1-05, bk-teh-1-06, bk-teh-1-07, bk-teh-1-09, bk-teh-1-11, bk-teh-1-12,
bk-teh-1-19, bk-teh-1-47`

## What was done

For each id, the printed page was rendered with pymupdf and the exact line boundaries
(stem's last line, options' first line) were read with `page.get_text("dict")`, not taken
on faith from `fig_windows.json` — that file's proposals are explicitly unvalidated outside
the 7 ground-truth windows (0031's own report says so), and four of these nine were in fact
badly off (see below). Every proposed crop was rendered standalone and eyeballed before
being applied, then the real pipeline (`book_figures.py` + `figures2.postprocess`) was run
and *those* output PNGs were opened and eyeballed too.

Added to `book_overrides.json`:
- `bk-teh-1-05, bk-teh-1-07, bk-teh-1-09, bk-teh-1-11, bk-teh-1-19` — new `reason:
  "figure-plain"` (new doc entry added to `_reasons`: the stem and options already parsed
  correctly, nothing to patch, only a crop window). Hand-measured windows because the
  auto-proposals for `bk-teh-1-11` (34pt short — stopped inside the coax-cable figure) and
  `bk-teh-1-19` (37pt long — would have swallowed the antenna-pattern figure's own two
  option rows) both missed the item's own ~10pt usability bar; `bk-teh-1-05`, `-07`, `-09`
  were within 1pt and used as-is.
- `bk-teh-1-04` — `reason: "figure-in-stem"`, **plus** a `question` patch. The parser had
  glued the figure's own "2 µF" component label onto the stem ("...prema shemi: 2uF"),
  the same x-column bug `book_figures.py`'s docstring documents for `bk-teh-5-60`. Also
  needed a **narrower** crop than full page width: this question's figure sits *beside*
  its (real, textual) options rather than above them, so a normal full-width crop would
  have captured "(a) 3 uF ... (d) 2 uF" inside the picture. `book_figures.py` had no way to
  express that, so it now accepts an optional `figure_x: [x0, x1]` alongside `figure:
  [y0, y1]` (defaults to full width when absent — every other override is unaffected).
- `bk-teh-1-06` — `reason: "figure-in-stem"` + `question` patch. Same bug: the stabilizer
  circuit's own "13 V nestabil." label bled onto the stem as a trailing "nestabil.".
- `bk-teh-1-12` — unchanged `question`/`options` (already correct from 0031's predecessor
  item), only a `figure` window added.
- `bk-teh-1-47` — the significant find. Its real options are four filter-response curve
  pictures (a/b/c/d), not text — but because there is no option *text* on the page for the
  column parser to anchor on, it had swallowed question 48's entire stem and options as if
  they were question 47's own continuation. The stored `question` was the two stems
  concatenated, and `options` were literally question 48's (`bk-teh-1-48`, already correct
  and unrelated, elsewhere in the file). Re-parsed by eye against the rendered page and
  entered with `reason: "figure-options"`, `figure_is_options: true`, and placeholder
  `"a)".."d)"` options — the same pattern as the six pre-existing figure-options entries.
  **This contradicts the item's own "Avoid" line** ("figure_is_options is false for all of
  these") — flagging per the brief rather than silently overriding it, but fixing it was
  necessary: leaving Q47 displaying Q48's unrelated options would have made it wrong, not
  merely undecorated. The position-based answer key was not touched — `book_keys.json`
  row 47 col I = `B`, which now correctly points at curve b), and was already `B` before
  (the parser computes it by position, not by option text, so the corruption never reached
  the answer, only the displayed choices).

In no case was any option text or answer key changed for a reason of my own physics —
`bk-teh-1-04`/`-06`'s garbled option text (`"I uF IE"`, `"SV"`) is pre-existing OCR noise,
left untouched and out of scope; only their stems were patched to drop the figure's own
bled-in caption.

## Deviation from `files:` (flagged per brief)

`fig_audit.py`'s calibration section assumed every override with a `figure` key also
carries its own `question`/`options` (true of the six pre-0032 entries, all eye-transcribed
for other reasons). The five new "figure-plain" entries don't — there was nothing to
transcribe — which crashed `fig_audit.py` with `KeyError: 'question'` and aborted
`rebuild.py`. Fixed by falling back to the question's own already-correct parse
(`book_parsed2.json`) when the override doesn't carry a duplicate copy; this is the file's
own `by_id` lookup it was already doing for `y_hint`, extended to the text too. Necessary
to satisfy the item's own "Done when: rebuild.py still reports 1176 questions" — not
otherwise widened.

`fig_windows.json` (also outside `files:`) changed as a mechanical side effect of running
`fig_audit.py` (part of `rebuild.py`'s pipeline, not something I hand-edited): 8 of its 9
skupina-I rows moved from "proposed" to "already fixed" and dropped out. Staged as-is
since it is a generated-but-tracked file and leaving it stale would misreport what's still
outstanding.
