because git ignores it — there is nothing to stage. `quiz/build/rebuild.py` is unchanged.

## What changed in `build_quiz.py`

1. Added `XREF_RE` and `appendNoteText(el, text)` right after `byId` is built (so it can close
   over the same lookup table used everywhere else for id resolution):

   ```js
   const XREF_RE = /(^|[^a-z0-9-])((?:bk-[a-z]+-\d+-\d+)|(?:[a-z]{3}-\d{2,3}[a-z]?))(?![a-z0-9-])/gi;
   function appendNoteText(el, text){
     XREF_RE.lastIndex = 0;
     let last = 0, m;
     while((m = XREF_RE.exec(text))){
       const id = m[2].toLowerCase(), start = m.index + m[1].length;
       if(!byId[id]) continue;               // shape matches, but no such question — leave as text
       if(start > last) el.appendChild(document.createTextNode(text.slice(last, start)));
       const a = document.createElement("a");
       a.href = "#q=" + id; a.textContent = m[2];
       el.appendChild(a);
       last = start + m[2].length;
     }
     if(last < text.length) el.appendChild(document.createTextNode(text.slice(last)));
   }
   ```

   The regex covers both id shapes actually in use (`teh-024`/`pro-011`/`prv-007`, with an
   optional trailing letter for the one `teh-186b`; and `bk-teh-1-01`-style). Boundaries use a
   captured non-`[a-z0-9-]` character (or start-of-string) before, and a negative lookahead for
   `[a-z0-9-]` after — no lookbehind, for older-engine safety, and it can't mistake a
   hyphenated non-id token (`"100 kHz-110 MHz"`, `"WRC-03"`) for a real id, since those don't
   have a non-word boundary on both sides of the digit run. Every candidate is still checked
   against `byId`; a shape match with no such question is left as the original plain text
   (`continue`, no early exit, so later valid ids in the same string still link).

2. Wired it into the note paragraph loop (was `p.textContent = para...`, now
   `appendNoteText(p, para.replace(/\n/g," "))`), which still builds `.wp` paragraphs as DOM
   nodes (`createElement`/`appendChild`), never `innerHTML` — the existing comment about why raw
   HTML injection is unsafe for note text is preserved (extended by one sentence noting the new
   link nodes follow the same rule).

3. Left `q.fx` (formula `<pre>` blocks) and the `q.lk` external-link nav untouched, per the
   item's "Avoid" — no scan inside formulas, `link_check.py`-covered code path unchanged.

4. Added `.wp a{...}` / `.wp a:hover,:focus-visible{...}` CSS, mirroring the existing `.lk a`
   accent-color/underline-on-hover treatment, so the new links are visually consistent with the
   "Dalje:" links already in the note body.
