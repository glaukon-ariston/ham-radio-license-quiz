## Two stems needed formula repair beyond the item's one named case

The item names only `bk-teh-6-14`'s height expression. Rendering all 9 pages found a
second, worse one:

- **`bk-teh-6-13`** — parsed stem was `"Tri kondenzatora kapaciteta € ,> CG, "` / `"Koliki
  je ukupni kapacitet C,, ?"`, having lost an entire clause (`spojena su serijski kao na
  slici`) and the `66 pF` value to OCR garbling of the subscripted formula line. Rendered
  the page and transcribed by eye: `"Tri kondenzatora kapaciteta C1 = C2 = C3 = 66 pF
  spojena su serijski kao na slici. Koliki je ukupni kapacitet CAB?"`. Options were already
  correct (`11/22/33/198 pF`) — only the stem needed the override's `question`/`options`
  pair (`options` is mandatory once `question` is set, since `book_figures.py`'s patch loop
  requires both).
- **`bk-teh-6-14`** — the item's named case, confirmed by eye: `"visini / = 2 2."` in the
  parse is OCR misreading `"visini h = 2 λ"` (zoomed to 5x to be certain of `h` vs `λ`
  vs the digit `2`). Options were also OCR-garbled versions of `λ`, `λ/2`, `3λ/2`, `4λ/2`
  (parsed as `%`, `a2`, `34/2`, `43/2`) — fixed alongside the stem for the same
  mandatory-pairing reason.
- Both use `reason: "stem-split-column"`, the existing taxonomy value from `bk-teh-3-01`
  (also a formula-heavy, subscript-garbled stem), rather than inventing a new reason string.
- **`bk-teh-6-01`** — not a formula garble but the `figure-in-stem` label-bleed pattern this
  cluster is named for: parsed stem carried a trailing `"U=100 V i"`, the circuit's own
  `U=100 V` node label glued onto the stem's last line by the parser's column-stitching
  (the exact bug class `book_figures.py`'s docstring documents for `bk-teh-5-60`). Stripped
  to `"Na shemi prikazani napon U = 100 V. Napon U, =?"`. While rewriting this entry's
  mandatory `options` pair, also restored the trailing `" V"` unit that three of the four
  options (`a`, `b`, `d`) were independently missing on the page (`c` already had it) —
  confirmed against the rendered page, not invented; this is not an answer or order change,
  same class of completion as sibling items' merged-block option fixes.

No answer letter was touched anywhere; `book_keys.json`'s skupina-VI column (position `6`
of each row) was checked for all 9 ids post-build and matches the assembled
`quiz/questions.json` exactly (d/a/c/b/a/c/d/b/c for -01/-05/-06/-13/-14/-16/-18/-19/-45).

## The other 6: figure-plain, windows measured by hand

`bk-teh-6-05, -06, -16, -18, -19` needed only a crop window; stems/options already parsed
correctly. `bk-teh-6-45` is the interesting one: its four options sit *beside* the
oscilloscope-grid figure (same layout hazard as `bk-teh-1-04`, which the codebase already
solved with `figure_x`), not below it — a plain full-width crop would have hung the
`(a)…(d)` option text into the image. Used `figure_x: [0, 220]` (the same device
`bk-teh-1-04` uses, options start at x=225.8) to clip it out.

All 9 windows were measured by hand from `page.get_text("dict")` line boundaries (stem's
own last line → next real boundary), not taken from `fig_audit.py`'s auto-proposals —
several of the 9 auto-proposals overshoot by 40–165pt (visible in the post-change
calibration table, e.g. `bk-teh-6-01`'s proposer runs to the *next question's* anchor at
435 instead of stopping at the true option-top 270, because it can't see the figure-in-stem
label-bleed text was already stripped from the geometry it measures against). Every
resulting PNG was opened and visually confirmed to show the whole figure and no option
text before this was called done.

## `bk-teh-6-11` — found, not touched, flagged for a human

question 11) sitting right next to this cluster: it already has a `book_overrides.json`

brief's "avoid widening scope" and the item's own "Done when" bar being specifically 0031's
9-id list for skupina VI, this was left untouched — flagged here for a future item rather
than silently fixed or silently ignored.
