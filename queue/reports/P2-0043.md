## How the exclusion works

In `main()`'s candidate loop: for each candidate, if `q["id"] in NO_FIGURE`, it is
appended to a new `excluded` list, the loop `continue`s before `propose_window()` is
called, and the id is **not** added to `outstanding` (so it never lands in
`fig_windows.json`) and **not** added to `unresolved` (so it doesn't read as "stem not
located" either). The printed per-row table shows `excluded` instead of `NO` for these
ids, and a new summary line `excluded (no fig): N [ids]` is printed alongside the
existing `unresolved`/`proposed` lines, so a human running the script can still see the
exclusion happened and why (the dict itself carries the reason).

`book_overrides.json` is untouched — `NO_FIGURE` is a fig_audit.py-only, in-memory
structure. The regression gate (`has_figure` vs `figs_book_index.json`, lines ~231-242)
reads `book_overrides.json`/`figs_book_index.json` only and was not touched; ran clean
both before and after this change (`all 83 applied figures still in figs_book_index.json`).

## What was deliberately not done

Did not tune `GAP_THRESHOLD` or `FIGURE_WORD` to make `-28`/`-30` pass "naturally" — per
the item's own **Avoid**. Did not backfill the exclusion list with other candidates from
skupina III-VI (0034-0037) even though those items' reports show similar false-positive
handling in prose (e.g. `bk-teh-4-37` in `queue/reports/P2-0035.md`) — that id is a
`stacked-options` override with no `opts`/`y` geometry, so it was never a `fig_audit.py`
candidate in the first place and doesn't belong in `NO_FIGURE`. Widening the seed list
beyond the two ids the item names would be scope creep; noting it here per the worker
brief instead.
