### `teh-201` — flag, newly surfaced

75 Ω → 300 Ω transformer, "omjer transformacije". Book/RK zbirka answer 1:2 is the *turns*
ratio; HRS's 1:4 is the *impedance* ratio (n=√4=2, Z-ratio=4). Both numerically correct for an
ambiguous phrase — not a numbering error, not law. Added `"flag": "check"` to the existing
`teh-201` entry in `quiz/build/notes_zzz_expanded_teh6_antene.json` (the note prose already
explained the distinction in depth; it only lacked the UI flag). This file is outside the
item's declared `files:` list — flagged here per the "touch a file outside your list" rule,
because "surfaced in the quiz like the other conflicts" (the item's own Done-when wording)
requires the flag mechanism, which lives in `notes_*.json`, not in `strict.py`/`overrides.json`.

### `teh-273` — flag, newly surfaced

Filter to suppress subharmonics+harmonics after a VHF TX: HRS marks (d) niskopropusni; the
book's own RK zbirka answer table marks (b) pojasnopropusni, and RK's own running prose (str.
192–193) agrees with the zbirka, not with HRS — a low-pass cannot suppress a subharmonic by
definition. Two independent RK sources against one HRS mark. Added `"flag": "check"` to the
existing `teh-273` entry in `quiz/build/notes_zzz_expanded_teh9_smetnje.json` (same rationale
as above; note prose was already thorough, only the flag was missing).

### `prv-009` — mapping bug, fixed in `strict.py`

HRS asks about **LSB**, book `bk-pra-5-05` asks about **USB** — genuinely different questions
(different KV segments, different sideband convention) that share a templated stem (≥0.90
plain-text similarity, one 3-letter run differs) and the same four band options, so the old
matcher paired them and reported a fake disagreement. Both answers are correct for their own
question.

Fix: added a `modes()` guard to `quiz/build/strict.py` — any emission-mode abbreviation (USB,
LSB, CW, AM, FM, SSB, FSK, RTTY, PSK, AFSK, SSTV, FAX, DSB, A1A, A3E, F1B, F3E, J3E) found in
either raw (un-normalised) stem must match before a pair is accepted.

A first attempt used a blanket "any ALL-CAPS token must match" guard instead of a curated mode
list. Tested against the full corpus, that version also excluded a previously-**agreeing**
ocr-anchor pair, `prv-004` ("Što znači kratica IARU?") vs the book's `bk-pra-2-18` ("...kratica
LARU?") — an I/L OCR glyph misread, the exact defect class documented in REVIEW.md §1
("`u.`→`11.`" etc.), not a different question. Both "IARU"/"LARU" and "USB"/"LSB" are
edit-distance-1 pairs, so edit distance alone can't tell them apart; only knowing which
abbreviations are semantically meaningful (modes) does. Narrowed the guard to the mode
whitelist, re-ran, confirmed the IARU/LARU pair is preserved as an agreement (ocr anchor stayed
80/80) and the USB/LSB pair is correctly excluded (interpolated dropped 28→27, disagreements
5→4).

Net effect: total comparable pairs 108→107, agreement 103/107=96.3% (was 103/108=95.4%). This
is a fixed false-comparable-pair, not a loosened check — the item's "avoid raising the
percentage by loosening the check" is satisfied because the check got *stricter* (added a
required condition), and the percentage rose only as a side effect of removing one incorrect
pairing.
