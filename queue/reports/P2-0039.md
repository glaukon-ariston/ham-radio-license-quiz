# P2-0039 — Turn the in-quiz breadcrumb into practice entry-point links

## What changed

`quiz/build/build_quiz.py`, `render()` (was lines 361-375, now ~363-399):

- Split the previously plain-text `SEC[q.s].name + sub` breadcrumb into two
  independently created DOM elements:
  - `secEl` — the section name (`SEC[q.s].name`).
  - `subEl` — the cjelina name (`q.sub`, numbering prefix stripped as before),
    only created/appended `if(q.sub)`.
- Outside exam mode (`!inExam`, where `inExam = S.mode === "exam"`), each
  element is an `<a>` whose `onclick` calls
  `start("practice", {filter: qq => qq.s === secKey})` (section) or
  `qq => qq.sub === subKey` (cjelina), with `secKey`/`subKey` captured as
  local consts from the *current* `q` at render time — this avoids the
  self-referential trap in the item text's literal example
  (`q => q.s === q.s`, which is always true regardless of section since it
  compares `q.s` to itself inside the callback where `q` is the *callback's*
  argument, shadowing the outer `q`). The closure-capture pattern matches
  `buildPicker()`'s existing `q=>q.s===k` and the `subTable` button's
  `q => q.sub === b.dataset.sub`.
- In exam mode (`inExam`), both elements are plain `<span>`s with no `href`
  or `onclick` — inert text, exactly like the neighbouring `q.id` tag, which
  was refactored to reuse the same `inExam` local instead of repeating
  `S.mode === "exam"` three times.
- Propisi/pravila questions have `q.sub` unset, so `subEl` is never created
  for them — only the section link renders, per the item's explicit
  instruction not to invent subsection data.
- Separator `" · "` between section and cjelina is appended as plain text
  outside both anchors, so only the name text itself is clickable (not the
  separator).

CSS: added `#qcrumb a{color:var(--accent);text-decoration:none;border-bottom:
1px solid transparent}` and the matching `:hover,:focus-visible` rule
(mirroring the existing `.lk a` pattern), since no generic `a{}` reset exists
in this stylesheet and the new anchors live inside `.eyebrow`/`#qcrumb`, not
inside `.tag` (which already has its own `a.tag` styling used only for the
id permalink).
