# P1-0038 — Fix confirm() no-op breaking exam start and quit in sandboxed iframe

## Root cause

All three call sites gated a real action on `window.confirm(...)`:

- `data-go="exam"` click handler (start exam)
- `$("#quit").onclick` (Prekini)
- `$("#reset").onclick` (Obriši napredak)

Inside a cross-origin sandboxed iframe without `allow-modals` (exactly how the page is
embedded on claude.ai — see the app's own comment at the top of the script about `#q=`
fragments not reaching a cross-origin frame), `confirm()`/`alert()`/`prompt()` are silently
no-ops: the call returns `undefined` (falsy) instead of throwing or showing a dialog, so
`if(confirm(...))` was always false and the buttons appeared dead.

## Fix

Added an in-page confirmation UI, built entirely from existing DOM/CSS conventions (`.btn`,
`.card`, `.nav`, the existing colour variables), no native dialog involved:

- **CSS** (`quiz/build/build_quiz.py`, next to `.hidden`): `.confirm-mask` (fixed-position
  backdrop) and `.confirm-box` (a small card centered in it, reusing `--card`/`--line`/
  `--shadow`).
- **HTML**: a hidden `#confirmMask` overlay with `#confirmMsg`, `#confirmYes`
  (`.btn.primary`), `#confirmNo` (`.btn`), inserted right before `<script>`.
- **JS**: new `askConfirm(msg, onYes)` helper (placed just above the `/* routing */`
  section) that shows the overlay, sets the message, focuses the Yes button, wires
  Yes/No clicks, dismisses on Escape or a click on the backdrop, and restores focus to
  whatever triggered it on close. `onclick` is reassigned per call (not accumulated), so
  no listener leak across repeated opens.
- Rewired all three call sites to `askConfirm(msg, () => ...)` instead of
  `if(confirm(msg)) ...`. No other logic touched — the exam timer/scoring and the
  `mode==="single"` visibility rule for `#quit` are untouched (verified by diff: only the
  three `onclick`/click-branch lines changed content, nothing else in `start()`/`show()`).

`alert("Nema pitanja u redu za ponavljanje.")` (wrong-queue-empty notice, line ~320) is a
separate no-op under the same sandboxing, but it wasn't named in this item's three call
sites and isn't a blocking action (nothing waits on its return value) — left alone per
"don't widen the scope," flagged here for a future item if Glaukon wants it too.
