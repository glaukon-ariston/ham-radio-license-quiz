## What landed

`quiz/build/make_packets.py` — the `--book` branch was rewritten from a topic cut (the

The HRS (non-book) branch is untouched: same `PACKETS`/`SPLIT` tables, same predicate loop,

## Why the topic cut was replaced, not kept alongside

The item's **Done when** is explicit about the target shape:
`work/packet_book_s<N>_<section>[_a|_b].json` for 18 skupina x section groups. That is a
different grouping key than the topic cut P2-0002 previewed in a scratch directory (its
report says as much: "into a scratch directory so as not to create files P2-0005 owns"). The
24 P3 book-notes items (`P3-0006`..`P3-0029`) each name a `packet_book_s<N>_<section>[_a|_b]`
file in their own `files:` list, so the skupina cut is the one downstream work is blocked on.
I did not keep the old topic-based `--book` output alongside it — the item names one shape,
and shipping two would leave it ambiguous which one the P3 items should trust.

## Grouping logic

For each skupina 1-6, for each section (tehnicki, propisi, pravila): filter `questions_extra`
to that (skupina, section) pair, sort by printed `number`. Tehnicki (60 per skupina) is split
into `_a`/`_b` by interleaving on that sorted order (`pool[0::2]`, `pool[1::2]`) — same
interleave technique already used for `teh3_krugovi_a/b` on the HRS side, so each half still
spans the whole exam paper rather than its first/second thirty. Propisi (20) and pravila (40)
stay whole — small enough for one item, and the P3 items' `files:` lists confirm no `_a/_b`
suffix is expected for those two.

Per-question body fields are byte-identical to the HRS packets (verified by set-equality of
keys on a sample pair): `number, subsection, question, options, answer, answer_text,
has_figure, current_explanation, current_cite, current_formula, flag, hrs_source`.
