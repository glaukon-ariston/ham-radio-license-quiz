# P2-0036 — Restore book stem figures: skupina V

## Scope confirmed

Ran `fig_audit.py` on the pre-change tree and filtered its candidate table to `bk-teh-5-*`,
`figure: NO`. That gave 17 ids (`-02, -04, -06, -07, -11, -15, -16, -19, -40, -41, -42, -46,
-47, -48, -49, -51, -55`), matching the item's own count of 17 exactly, plus `bk-teh-5-44`
(already in `book_overrides.json`, excluded from the candidate table because an override
entry carries no parser geometry) needing only a `figure` key, per the item.

## Three of the 17 are false positives — verified geometrically, not just by eye

Before touching anything, every one of the 17 was rendered (pymupdf, 200dpi) and cross-checked
against `page.get_text("dict")` line boundaries. Three have **no room for a figure at all**:

- **`bk-teh-5-02`** — real gap between the stem's own last line (y=282.7) and the first
  option (y=298.9) is 16.2pt. GAP detector fired at 62.7pt only because it measures from the
  *top* of the (2-line) stem block, not its bottom — an inflation the detector's docstring
  itself doesn't account for.
- **`bk-teh-5-06`** — same story, 15.6pt of real gap; NAME detector fired on "krivulje
  odziva" ("response curve"), ordinary physics vocabulary, not a reference to a picture.
- **`bk-teh-5-15`** — 19.6pt of real gap; NAME fired on "spektar" (spectrum), again just
  vocabulary, no picture on the page.

All three were rendered and visually confirmed empty between stem and options (page 327/329
images). No `figure` was added for these three — adding one would crop either whitespace or
bleed into the next question's text. This is the same category of exclusion 0035 made for
`bk-teh-4-37` (checked by eye, confirmed not needing a figure, left alone). They still print
as `NO` in `fig_audit.py`'s per-run candidate table (the script has no way to record "verified,
no figure exists" — it only gates regressions), but the calibration section and this report
both document why. `fig_windows.json`'s own proposals for these three land off the page
entirely (e.g. `bk-teh-5-02` → `[283, 802]`, `bk-teh-5-06` → `[727, 802]`) — further evidence
they're detector noise, not a missed figure.

## The 14 real ones, and two merged-block defects found by rendering (not named in the item)

Windows were measured by hand from `page.get_text("dict")` (stem's own real last line → next
option's first line), not taken from `fig_windows.json`'s auto-proposals — spot-checking
confirmed several proposals were unusable (e.g. `bk-teh-5-07` proposed `[92,276]` bleeds into
option text at y=231 because both options are too short for the proposer's "real option"
threshold; `bk-teh-5-51` proposed `[352,505]` similarly overshoots past the real option start
at y=458.7). Every window was confirmed by opening the resulting PNG after the real pipeline
run.

- **`bk-teh-5-04`** — `figure-in-stem`: stem read `"...služe da: — IE HB o"`, the trailing
  debris being the RC circuit's own "R"/"Si" labels bleeding into the stem column. Stripped to
  `"...služe da:"`; options unchanged (already correct).
- **`bk-teh-5-07`, `-11`, `-16`, `-19`, `-40`, `-41`, `-46`, `-48`, `-51`** — `figure-plain`,
  stem/options already correct, only a crop window added.
- **`bk-teh-5-42`** — `cross-reference`: "Kolika je frekvencija signala sa oscilograma iz 41.
  zadatka?" reads the same oscillogram as `bk-teh-5-41` (same page, 334) — not named in the
  item but the same species as the item's own `bk-teh-5-49` case. Copies `-41`'s window
  verbatim rather than proposing a fresh one, per precedent (`bk-teh-3-43`/`-54`).
- **`bk-teh-5-49`** — `cross-reference`, the item's named case: shares `bk-teh-5-48`'s picture
  but sits on a **different PDF page** (336 vs 335) — the first cross-page reference in this
  cluster. Handled by setting the override's own `page: 335` (borrowed) with `-48`'s window,
  so `book_figures.py`'s per-entry `page` lookup crops from the correct source page into a
  fresh `bk-teh-5-49.png`, literally "crop it twice" rather than chasing the reference at
  render time. Confirmed the resulting PNG is byte-identical to `-48`'s.
- **`bk-teh-5-44`** (pre-existing entry, per the item) — only `figure: [529, 739]` added,
  `reason`/`question`/`options` untouched.
- **`bk-teh-5-47`** — `figure-in-stem`, **not named in the item**, found the same way as
  `-04`: the parsed stem's trailing `"...Sintezator treba: Razina signala"` — "Razina signala"
  ("signal level") is the spectrum chart's own rotated y-axis label, glued onto the stem by
  the same column-stitching bug. Stripped; options unchanged.
- **`bk-teh-5-55`** — the significant find, **not named in the item**, same species as 0035's
  `bk-teh-4-47`/`-48`: the coordinate parser's raw record for `bk-teh-5-55` had **`bk-teh-5-56`'s
  stem and options** stitched onto it verbatim (55's own options are four filter-response
  curves with no text at all, so the parser fell through to the next real text block — 56's).
  Rendering page 337 (printed 342) confirmed 55's real stem is "Naš odašiljač može raditi u
  cijelom kratkovalnom području. Koji od ponuđenih filtara bi uspješno ograničio harmonička
  zračenja?" followed by four labelled curve panels (a/b/c/d), and 56 is a separate,
  already-correctly-overridden question ("Provjerili smo da RF smetnje..."). Fixed by
  converting `bk-teh-5-55` to a `figure-options` entry (options `a)`/`b)`/`c)`/`d)` placeholder,
  `figure_is_options: true`, window `[401, 613]` covering all four curves) — the answer letter
  is untouched throughout (still resolved by position from `book_keys.json`, independent of
  the override's `options` content, confirmed via the assembled `quiz/questions.json`).
  `bk-teh-5-56` was not touched and still resolves correctly on its own.

In no case was an answer letter touched. `figure_is_options` is `true` only for `bk-teh-5-55`
(genuinely picture options, matching the item's Avoid exemption logic) and `false` for
everything else added here. `bk-teh-5-52` (already `figure-options`, a genuine figure-*options*
question) was not touched, per the item's Avoid.
