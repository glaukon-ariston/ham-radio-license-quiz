# P3-0007 — Book notes, skupina I tehnički (b)

## Scope

Wrote `quiz/build/notes_book_s1_tehnicki_b.json`: one teaching note per id in
`quiz/build/work/packet_book_s1_tehnicki_b.json` (30 ids, `bk-teh-1-02` through `bk-teh-1-60`,
even numbers only — same probni ispit as P3-0006's `_a`, which took the odd numbers). Same
simple `{note, formula?, cite}` shape as `notes_book_s1_tehnicki_a.json`; no links section.

## What was done

- Rendered/read the actual printed pages 288-297 of `Radiokomunikacije.pdf` with
  `booktool.py`/pymupdf for all 30 questions, not just the packet's OCR text — three of the
  30 carry a figure that `get_images()`/`get_drawings()` cannot see (same PrimoPDF trap as
  P3-0006): `bk-teh-1-04` (capacitor network), `bk-teh-1-06` (Zener+transistor voltage
  stabiliser), `bk-teh-1-12` (PLL block diagram). Rendered `bk-teh-1-06` at 600dpi to identify
  the circuit element that low-res scan made ambiguous — it is an NPN transistor (base down to
  the Zener node, collector to the raw 13V rail, emitter with arrow up to output A), confirming
  the circuit is an emitter-follower series regulator before writing the note around it.
- **Cross-checked all 30 answer letters against the book's own printed key table** ("ODGOVORI
  NA PITANJA", Skupina I column, RK tiskana str. 354-355 — rendered as an image, not just OCR,
  per rule 3) rather than trusting the packet's own `answer`/`options` fields blindly. All 30
  match the table exactly. This surfaced a packet-generation bug (see below) but no answer-letter
  problems — nothing here triggers rule 1.
- Verified every citation against the book's own section headings/page content (not invented
  numbers): e.g. `1.3.1. Jakost električnog polja` (str. 33) for the two E=U/d questions,
  `1.3.2. Zaštita oklapanjem od djelovanja električnog polja` (str. 34) for the shielding-materials
  question — this section literally says "Elektronske cijevi oklapale su se metalnim tuljcima...
  Oklapanje električnih vodova izvodi se bakrenim opletima", matching the exam's "metalnih
  tuljaca, kućišta i opleta" almost verbatim. `9.2. Uzroci smetnja` (str. 192) for the two
  harmonic-lands-in-band questions turned out to be the source text the exam questions were
  lifted from almost word for word ("Odašiljač koji radi u amaterskom području 50...51,9 MHz
  svojim drugim harmonikom lako upada u frekvencijsko područje 100...103,8 MHz VHF/FM radija").
- Worked the physics for every calculation (ERP in dB, series/parallel capacitor network, E=U/d,
  Q=f0/bandwidth, Ω/V sensitivity, W=P×t energy) by hand and cross-checked the result against the
  book's own verified answer letter before writing the note — per rule 1, this was a check, not
  a rewrite; nothing changed as a result.

## One thing found, not fixed

**Packet option-text bug (not an answer-letter bug) on two questions.** Rendering the actual
printed page 291 image (not just its OCR text) for `bk-teh-1-20` and `bk-teh-1-22` shows their
printed options in order a,b,c,d; the packet's own `options` dict for both has pairs (a,b) and
(c,d) swapped relative to that image — e.g. printed Q20 is `a)50 b)100 c)500 d)1000` but the
packet lists `a:100 b:50 c:500 d:1000`. The packet's `answer` **letter** is still correct in both
cases (verified against the key table in str. 354-355, not just recomputed from physics) — `b`
for Q20 really is the physically-correct Q=100, and `d` for Q22 really is "E i F" per both the
book's own printed page and its answer table — so this did not trigger rule 1 and needed no
report as a wrong-answer flag. But anyone reading the packet's own `options` field for these two
ids would see mismatched text-to-letter mapping, the same class of bug P3-0006 found for
`bk-teh-1-47` (stale packet vs. current `book_overrides.json`) though a different mechanism here
(a rendering/column-order bug in `make_packets.py`, not staleness). My notes describe the
physics/correct value directly rather than quoting the packet's option text, so this doesn't
affect what shipped, but it's worth widening the `make_packets.py` regeneration item (already
flagged by P3-0006) to also re-verify a/b/c/d assignment against a rendered page image, not just
OCR block order, for any question drained after this one.

Also confirmed (again, as P3-0006 already flagged) that `rebuild.py`'s note-attachment loop still
only builds `byid` from the 456 HRS bank questions, so none of these 30 notes attach to a served
question yet — this run's own output repeats `! notes for unknown ids` for all 30 new ids. Not
re-flagging as new; it's the same open item P3-0006 already surfaced.
