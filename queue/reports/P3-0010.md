## Three found-not-fixed data corruptions (not caused by this item, not in its `files:`)

While cross-checking every option's text and order against the actual printed page (not just
trusting the packet), I found that **three of the 30 live/packet questions have scrambled
options** — the option *text* doesn't match the option *letter* the HRS answer key intends,
even though the packet's `answer` letter itself is unchanged and still correct per the key
table (`book_keys.json`). This is a `parse_book2.py`/`book_overrides.json`-level defect, not
something introduced by this item, and not something I fixed (out of scope — `files:` for this
item is the packet, read-only, and the notes file).

1. **`bk-teh-2-03`** — the four live options ("detektor ovojnice / ratio detektor / AM-detektor
   / punovalni ispravljač") are actually **question 4's** options ("Sklop na slici je:"), not
   question 3's own. Question 3's real options are four picture-only frequency-response curves
   (str. 298) — I rendered the page and confirmed this by eye. The HRS-key letter `d` is still
   correct for the *real* question (the low-pass curve, correct choice for band-limiting mic
   audio), so I wrote the note around the real, verified content, the same way P3-0006 handled
   the analogous `bk-teh-1-47` case — except here there is **no override yet** fixing the live
   build (unlike `bk-teh-1-47`, which `book_overrides.json` already patches), so the shipped
   quiz currently shows the wrong four options text for this question.
2. **`bk-teh-2-13`** — live options **a and b are swapped** relative to the printed page. Real
   page: a=30 MHz, b=300 MHz. Live/packet: a=300 MHz, b=30 MHz. HRS key column II = `B`, which
   correctly names the real page's option b (300 MHz — also the physically correct answer,
   f=c/λ). Live currently shows "b) 30 MHz" under the marked-correct letter, which is wrong.
3. **`bk-teh-2-29`** — live options **c and d are swapped** relative to the printed page. Real
   page: c=180°, d=360°. Live/packet: c=360°, d=180°. HRS key column II = `C`, naming the real
   page's option c (180° — confirmed by the book's own worked example on str. 172, and by my own
   calculation φ=360°×3/6). Live currently shows "c) 360°" under the marked-correct letter, which
   is wrong.

For all three, the note text describes the verified-correct physics/content and cites the real
source; it does not quote or affirm the currently-wrong live option text. **Not fixed**:
`book_overrides.json`/`parse_book2.py` aren't in this item's `files:`, and per rule 1 this is a
transcription/parsing defect to flag, not a rewrite to make myself. Given P3-0006 already found
`bk-teh-1-47` had exactly this failure mode, and the packet-staleness note there said "other
still-open packets likely have the same staleness" — this confirms that warning: the corruption
isn't limited to stale packets, it can be live-and-shipping too. **Worth a queue item**: audit
every packet's options against the rendered page image (not just the OCR'd text order) before
draining the remaining `_b`, `pravila`, `propisi` skupina-II-through-VI items, since this
worker only checked its own 30 by hand.

Also, minor and non-corrupting: **`bk-teh-2-01`** option `a`'s live text is truncated to "4230"
(missing "Ω i 5170 Ω") — the real page reads "4230 Ω i 5170 Ω". Doesn't change the answer letter
or the note's correctness, just a cosmetic parse truncation, flagged for the same future cleanup.
