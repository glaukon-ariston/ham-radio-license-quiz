# P2-0058 — Document GitHub Pages publish workflow for the built quiz

## What was done

Wrote `PUBLISHING.md` at the repo root covering all four required pieces from the item file:

1. **Local rebuild.** `python quiz/build/rebuild.py`, noting it requires the local, untracked
   `docs/` directory and derives its output location from its own file path (`quiz/build/`'s
   parent), not cwd — confirmed by reading `quiz/build/rebuild.py`'s `HERE`/`DST` definitions
   and its `SOURCES` dict (every entry points at `docs/*.pdf`).
2. **How the gitignored output reaches `gh-pages`.** Chose a standalone **orphan branch**
   named `gh-pages`, populated via `git add -f quiz/quiz.html quiz/questions.json
   quiz/images/` (the `-f` needed because `.gitignore` excludes all three everywhere else,
   by design, per its own comment about keeping branches mergeable). Documented *why* over
   the alternatives considered: a worktree would also work but adds a second on-disk checkout
   to track; publishing straight from `main` was rejected because it would recreate exactly
   the merge-conflict problem `.gitignore` exists to avoid; the branch is orphaned (not
   forked from `main`) so it doesn't carry unrelated history (including `docs/`'s
   pre-P1-0056 history).
3. **One-time GitHub setting.** Settings → Pages → Deploy from a branch → `gh-pages` / root,
   with a note on the resulting URL shape (`quiz/quiz.html` stays under `quiz/` even on
   `gh-pages` — nothing relocates it to branch root) and a pointer back to README.md's
   existing `_(link goes live once GitHub Pages is set up — see P2-0058)_` placeholder.
4. **Re-publish procedure.** Same two commands (rebuild, then commit+push on `gh-pages`),
   with an explicit warning that `quiz/images/` must be re-added in full every time —
   filenames aren't content-hashed, and `rebuild.py` itself prunes stale PNGs locally
   (prints "N stale removed"), so a partial `git add` on `gh-pages` would leave orphaned
   images live on the published site.

Also stated explicitly, per the item's "Avoid": **no CI/GitHub Actions build** — `docs/` is
being deliberately kept out of the public repo (P1-0055/0056), so a CI checkout has nothing
for `rebuild.py` to read; a future reader is told this directly so they don't add a workflow
that will fail.
