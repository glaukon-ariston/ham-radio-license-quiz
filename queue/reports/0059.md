# P2-0059 — Replace the 3-palette color themes with light, dark, and a waterfall theme

## What changed

`quiz/build/build_quiz.py` only (the file named in `files:`). Net -15 lines (71 added, 86
removed) — most of the removal is the two now-deleted palette blocks (balanced, vivid) each
with their four-block light/dark/media shape.

1. **CSS**: the `:root` / `@media(prefers-color-scheme:dark)` / `[data-theme="dark"]` /
   `[data-theme="light"]` / `[data-palette="balanced"]` (x4) / `[data-palette="vivid"]` (x4)
   ten-block cross is gone, replaced by exactly three flat blocks:
   `:root[data-theme="light"]`, `:root[data-theme="dark"]` (both byte-identical to the old
   "muted" palette's light/dark values, as the item required), and a new
   `:root[data-theme="waterfall"]`. No `@media(prefers-color-scheme)` anywhere in the
   stylesheet any more — a bare `:root{}` keeps only the two theme-independent tokens
   (`--mono`, `--sans`).
2. **Waterfall theme**: near-black `--paper:#05080A` / `--card:#0B1116`, phosphor-cyan
   `--accent:#00E5C7`, hue-separated `--good:#7CFF6B` (lime) / `--bad:#FF5C6C` (red-pink) /
   `--warn:#FFC93C` (amber), an accent-tinted glow baked into `--shadow` (adds a cyan
   `0 0 20px -4px rgba(0,229,199,.5)` glow layer to the usual two-layer shadow), and a new
   `--fx-gradient:linear-gradient(90deg,#7C3AED,#06B6D4,#22C55E,#F59E0B,#EF4444)` token
   (violet→cyan→green→amber→red). Covers all 15 pre-existing tokens plus the new one.
3. **The couple of additive rules consuming `--fx-gradient`** (both via
   `var(--fx-gradient, <safe-fallback>)`, so light/dark render byte-identically to before):
   - `header.bar::after` — a static 2px spectrum hairline under the sticky header
     (fallback `transparent` = invisible outside waterfall).
   - `.meter i` (score-bar neutral fill) — fallback `var(--accent)`, i.e. exactly what it
     rendered before; the higher-specificity `.meter i.ok`/`.meter i.no` rules (unchanged)
     still always override it with a solid `--good`/`--bad` once a result is known, in every
     theme, so pass/fail colour-coding never depends on the gradient.
   No animation was added anywhere; both are static, and the existing global
   `prefers-reduced-motion:reduce` rule (untouched) still governs the rest of the page.
4. **JS**: `LS_THEME`/`PALETTES`/`palette` → `LS_THEME = "9a-ispit-theme"`,
   `THEMES = ["light","dark","waterfall"]`, `theme`. The pre-paint inline `<script>`
   (right after `</style>`) now: best-effort `localStorage.removeItem("9a-ispit-palette")`
   (no value mapping — muted/balanced/vivid don't correspond 1:1 to light/dark/waterfall),
   then reads `"9a-ispit-theme"`; if it isn't exactly `"light"`/`"dark"`/`"waterfall"`, falls
   back to `matchMedia("(prefers-color-scheme: dark)")` → `"dark"` or `"light"` (never
   `"waterfall"`), and sets `document.documentElement.dataset.theme` before first paint — a
   `catch` also defaults to `"light"` if storage access itself throws (the page can run in a
   sandboxed iframe). The main script's theme block now just reads back
   `document.documentElement.dataset.theme` (already resolved by the pre-paint script) instead
   of re-deriving it, so the two scripts can't disagree; it wires `#themeSel` and persists
   changes under the new key.
5. **`<select id="themeSel">`**: three options — `light`→"Svijetlo", `dark`→"Tamno",
   `waterfall`→"Vodopad" ("vodopad" is the standard Croatian term for an SDR waterfall
   display, thematically apt).
6. **Narrow-viewport label map** (`applyNarrowHeaderLabels`): updated to the new
   light/dark/waterfall keys. Unlike `srcSel`, all three new labels are already short
   ("Svijetlo"/"Tamno"/"Vodopad" — 5–8 chars, comparable to the *narrow* abbreviation
   "Uravnot." the old vivid/balanced scheme needed at full width), so one label map now
   covers both widths instead of two branches with the same content — noted in a code
   comment so it doesn't read as an oversight.

## Why these hexes (waterfall)

Wrote a one-off WCAG contrast script (relative-luminance formula, not a library — same
method P2-0041 used) and checked every text-bearing pair the item lists for waterfall:
`ink/paper` 19.20:1, `ink/card` 18.15:1, `muted/paper` 6.73:1, `accent/paper` 12.46:1,
`accent/card` 11.78:1, `paper`-on-`accent` (`.btn.primary`) 12.46:1, `good/good-soft`
12.01:1, `bad/bad-soft` 5.60:1, `warn/warn-soft` 9.34:1 — all comfortably ≥4.5:1 on the
first draft, no iteration needed. Light/dark reuse the pre-existing "muted" hexes verbatim
(unchanged, so their pre-existing contrast numbers from P2-0041's report still apply).
