# P2-0040 — Unify area/cjelina breakdown across home and practice picker

## What changed

`quiz/build/build_quiz.py` only, as scoped by `files:`.

1. **New shared helper `sectionGroups(k)`** (inserted just above `home()`,
   ~line 550), extracted from the stats loop that used to live only inside
   `home()`'s `subTable` build. For a section key it returns one group per
   cjelina if `q.sub` exists anywhere in that section (currently true only
   for `tehnicki`, whose 641/642 questions carry a subsection), or a single
   `{name: SEC[k].name, sub:null, qs:<all of them>}` whole-area group
   otherwise (`propisi`, `pravila` — per the item's scope constraint, no
   cjelina vocabulary exists for these and none was invented). Each group
   carries its own `seen/ok/tries` computed the same way the old inline code
   did.

2. **`home()`'s `subTable`** now loops `for(const k of Object.keys(SEC))` and
   calls `sectionGroups(k)` instead of hand-building a `tehnicki`-only `subs`
   map. Rows now cover all three sections: 10 cjelina rows for tehnicki, one
   whole-area row each for propisi and pravila (12 rows total, was 10). The
   heading changed from "Tehnički dio po cjelinama" to "Po cjelinama" and the
   first column header from "Cjelina" to "Cjelina / područje", since the
   table is no longer tehnicki-only. Each row's "Vježbaj" button now carries
   both `data-sub` (empty string for whole-area rows) and `data-sec`; the
   click handler filters by `q.sub` when present, else falls back to `q.s`
   — this is what lets the whole-area rows work without a fake subsection
   value.

3. **`buildPicker()`** still adds one whole-area button per section exactly
   as before (`meta.name`, filter `q=>q.s===k`), then — only when
   `sectionGroups(k)` returns more than one group, i.e. only for tehnicki —
   adds one button per cjelina, title = cjelina name with the leading
   "N. " numbering stripped (matching the existing breadcrumb convention in
   `render()`), description naming the parent section plus "Viđeno N ·
   X% uspješnost / još bez pokušaja", filter `q=>q.sub===g.sub`. For
   propisi/pravila the `groups.length > 1 || groups[0].sub` guard is false,
   so no extra buttons are added beyond the whole-area one already there —
   satisfying "Done when" #2 (single whole-area entry, not absent) without
   inventing subsection rows.
4. The two existing "Sve iz HRS lista" / "Dodatna iz priručnika" picker
   buttons are untouched, still appended last, same filters.

Both `home()` and `buildPicker()` now call the same `sectionGroups()` — no
second implementation of "group questions into cjelina-or-whole-area with
stats" exists in the file (Done-when #3).

Coordination with item 0039 (already `done`): 0039's breadcrumb links and
this item's picker/home buttons both call `start("practice", {filter})`
with a closure-captured key; I did not touch `render()`'s breadcrumb code
and did not need to — the filter-building pattern was already identical
before this item (`q=>q.sub===key` / `q=>q.s===key`), so nothing to
consolidate further.
