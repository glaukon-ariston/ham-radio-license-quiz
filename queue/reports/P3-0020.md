## Why this item got full word-for-word verification

The handoff named three earlier pravila/propisi failure modes (wrong article content, wrong
number/frequency range, note-vs-cite page mismatch) plus P3-0016's single-page-within-a-compound-
citation error, and named P3-0013/P3-0017 as the two that got it right by verifying every
citation independently, including each page of a multi-page cite separately. I treated this
packet the same way: every numeric/frequency/prefix/Q-code claim was pulled and read directly
from the source PDF with `booktool.py`/pymupdf before it went into a note, never reused from the
packet's own `current_cite` (which for all 40 ids is only `"tablica ODGOVORI NA PITANJA"`, i.e.
the answer-key table location, not a content citation) or from its `hrs_source` page numbers.

## Packet's `hrs_source` page numbers are off by one, same bug as P3-0013/P3-0016/P3-0017

`booktool.py find RK "SKUPINA IV."` shows the pravila exam paper's "SKUPINA IV." heading at
printed **393**, not 392 as every `hrs_source` in this packet claims. Dumped and read printed
393, 394, 395, 396, 397 directly and mapped every question to its real page (q1-7→393, q8-15→394,
q16-23→395, q24-31→396, q32-40→397) before citing anything. Not fixed in the packet (out of this
item's `files:`); every `cite` in the notes file uses the page verified live.

## Answer-key table verified from the rendered image, not from the packet's `answer` field

`get_text()` on RK printed 409-410 ("ODGOVORI NA PITANJA... C) HRVATSKA I MEĐUNARODNA DJELATNA
PRAVILA I POSTUPCI") returns only the row numbers, not the letter grid — the grid itself is a
graphical table the OCR text layer doesn't carry (same PrimoPDF-table trap the handoff warns
about for figures, but here for a data table instead of a circuit). Rendered both pages as images
with pymupdf and read the Skupina IV column by eye for all 40 rows; every one matches the
packet's own `answer` field exactly — so I did not have to override any HRS-marked letter, but I
did not take the packet's word for it either.

## Two verified, unfixed discrepancies (flag: check)

- **bk-pra-4-13** (long-wave range): the exam's own printed option (a), which the key marks
  correct, reads "od 20 kHz do 300 kHz" (confirmed by rendering the page as an image, not just
  OCR text, since a truncated/garbled digit was exactly the kind of error this series has hit
  before). RK's own spectrum table (Tablica 1.5.1., str. 38) defines LF ("kilometarski valovi",
  i.e. long waves) as 30...300 kHz. Same book, two different lower bounds for the same band. Not
  fixed — flagged and explained, HRS's (a) left standing.
- **bk-pra-4-29** (repeater RV58 frequencies): the exam's option (a), which the key marks
  correct, reads "TX/RX 144,725/144,125". RK's own repeater-channel table (str. 280) gives RV58 as
  input 145,125 MHz / output 145,725 MHz — i.e. the physically correct pair is 145,725/145,125,
  which in this exam variant is option (c), not (a). This is not a guess: the *same question*
  appears in SKUPINA V (str. 401) with the options reordered so that 145,725/145,125 sits under
  letter (a) there, and SKUPINA V's own key also marks (a) — two independent exam variants agree
  on the true value, and SKUPINA IV's printed "144,725" is a one-digit typo (145→144) that
  propagated into that variant's key. Per rule 1, HRS's answer for SKUPINA IV was left untouched;
  the note explains the discrepancy and cites RK str. 280 plus the SKUPINA V cross-check plus the
  answer-key table image itself.
- The companion fact, **bk-pra-4-14** (RV56 = 145,100/145,700), was independently confirmed
  correct against the same str. 280 table — no flag needed there.

## Other verification notes

- Q-code and operative-abbreviation facts (LOG, QRV, QTR, NAME, QRB, RST, UTC, 73, GB/ES/GL/GN,
  PSE/UR/AGN, KN, SOS) were all read directly off RK's own tables (str. 251, 253-256), with str.
  253 additionally *rendered as an image* because that page's `get_text("blocks")` output visibly
  interleaves two columns (labels then definitions, offset by several rows) for the HR...LSN
  stretch — a second OCR-column trap distinct from the PrimoPDF-image one already known from this
  series, worth naming for whoever touches this page next.
- Country-prefix questions (S5/TA/OH/GM/OZ/SM → Slovenia/Turkey/Finland/Scotland/Denmark/Sweden)
  were cross-checked against both RK's own DXCC list (str. 257-258) and PZM's European-prefix
  table (str. 142), not just one source.
- Operating-procedure claims (check-frequency-before-CQ, no-CQ-over-a-repeater, CQ-allowed-on-
  simplex, VHF DX >300 km, directed-call etiquette for bk-pra-4-01/32) were traced to PZM's Tema
  23/28 procedure text (str. 139, 147-148), not asserted from general ham-radio knowledge.
- One id, **bk-pra-4-23** ("telekomunikacije" definition), could not be traced to an explicit
  RK/PZM/NN150/22 definition of the word itself despite searching the front matter and the ITU-RR
  section — the note says so and cites only the verified exam page, per the Avoid clause ("cite
  nothing rather than a plausible page").
