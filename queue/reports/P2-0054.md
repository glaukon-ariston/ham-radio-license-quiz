## #1 — Screen transitions don't move focus

Gave each of the four top-level sections exactly one heading with `id` + `tabindex="-1"`:
`#home`'s existing `<h1>` (`id="homeH"`), `#picker`'s existing `<h2>` (`id="pickerH"`),
`#result`'s existing `<h2 id="resTitle">` (just added `tabindex="-1"`), and a **new** heading for
`#quiz` — `<h2 id="quizH" tabindex="-1" class="vh">Pitanje</h2>` — since that screen previously had
no static `<h1>`/`<h2>` at all (its visible "header" is the dynamic `#qcrumb` breadcrumb built in
`render()`); `.vh` is a standard clip-based visually-hidden utility (new CSS rule) so it's a real
focus target without changing the visible layout.

`show(id)` now ends with:
```js
const h = $("#"+id).querySelector("h1[tabindex],h2[tabindex]");
if(h) h.focus({preventScroll:true});
```
Deliberately placed only in `show()`, not `render()` — confirmed by reading every call site
(`start()`, `finish()`, `leaveQuiz()`, the `data-go` click handler, `hashchange`, `openById`) that
`show()` is the single chokepoint for all four screen transitions, and that `render()` (called on
every next/prev/pick inside an already-open quiz) never calls `show()` — so this doesn't steal
focus back on every option click, only on actual home/picker/quiz/result switches, matching the
review's own scoping ("every single navigation," not every interaction).

## #2 — Correct/incorrect is color-only

In `render()`'s `it.order.forEach` loop, inside the existing `if(it.done)` block (so it inherits
the same exam-mode gate that already keeps `.ok`/`.no` hidden until `finish()` — nothing changed
about when this fires, only what it adds): for the correct option, appends
`<span class="mk" aria-hidden="true">✓</span><span class="vh"> (točan odgovor)</span>` right
after the `.k` span; for a wrongly-picked option, the same with `✗` and
`(tvoj odgovor, netočno)`. `.mk` is a decorative, `aria-hidden` glyph styled to match `.ok`/`.no`'s
existing green/red (new `.opt.ok .mk`/`.opt.no .mk` CSS rules, same pattern as the pre-existing
`.opt.ok .k`/`.opt.no .k`); `.vh` (the same new utility from #1) carries the actual
screen-reader-only word. Verified in the built page's markup that the glyph+text land in the DOM
only when `it.done` — i.e. never mid-exam.

## #3 — Sticky header has no narrow-viewport plan

Went with the review's smaller option (a) — shrink option text under a `max-width:480px` media
query — extended to also cover the fact that `#srcSel`'s labels are *worse* than the review
measured: they carry a live question count appended in JS (`"HRS + priručnik (1176)"`), not just
the static string in the HTML template. Replaced the old one-time static
`$("#srcSel").querySelector(...).textContent = ...` assignment with
`applyNarrowHeaderLabels()`, driven by `window.matchMedia("(max-width:480px)")`: at normal widths
it reproduces the exact original strings (`"Samo HRS lista (N)"` / `"HRS + priručnik (N)"`,
`"Prigušeno"`/`"Uravnoteženo"`/`"Živopisno"`) — the wide-viewport path is byte-identical to
before — and under 480px switches to `"HRS (N)"`/`"HRS+kn. (N)"` and `"Uravnot."` for the
balanced palette. Wired to `narrowMQ.addEventListener("change", ...)` so it re-evaluates live when
a devtools responsive view crosses the breakpoint, not just on load. Added a matching CSS
`@media (max-width:480px)` block that shrinks `.barin` gap/padding, `.brand` and `.themesel` font
size, and `.tick` padding, plus `flex-wrap:wrap` on `.barin` as a last-resort fallback (only
engages if the row still doesn't fit — never affects normal-width rendering, and wrapping is not
the same failure mode as clipping/horizontal-scroll, so it satisfies the requirement even if my
own row-width arithmetic is slightly off).
