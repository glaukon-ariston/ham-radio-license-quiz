## Page-mapping bug found and worked around

The packet's `hrs_source` field is off by exactly one printed page throughout, the
same systematic bug documented in `notes_book_s4_pravila.json`. It claims questions
1–40 sit on printed pages 397–401; the real "SKUPINA V." heading begins on printed
**398** (confirmed with `booktool.py find RK "SKUPINA V"` → pdf 391 = printed 398, and
by reading the page — it opens with question 1, "PSE 5 UP"). I read all five real
pages directly:

- q1–7  → printed 398
- q8–16 → printed 399
- q17–24 → printed 400
- q25–32 → printed 401
- q33–40 → printed 402

Every question's text and all four options were compared word-for-word against these
five pages (full dumps captured via `booktool.py page RK <n>`). All matched the packet
exactly (this packet's OCR is clean — pravila text has no formulas/Greek letters to
corrupt, unlike the tehnicki packets).

## Answer-key verification

`ODGOVORI NA PITANJA, C) HRVATSKA I MEĐUNARODNA DJELATNA PRAVILA I POSTUPCI` spans
printed 409–410. Because this is a table image (line art, not extractable OCR columns
— same PrimoPDF pattern the brief warns about), I rendered both pages with PyMuPDF at
3x and read the "Skupina V" column by eye, all 40 rows. Every one of the 40 letters
matches the packet's `answer` field exactly — no transcription errors, no flags
needed for this packet.

I specifically re-checked q29 (RV58 repeater channel), since `notes_book_s4_pravila.json`
flagged the *equivalent* Skupina IV question for a wrong HRS letter there. I rendered
RK's own repeater-channel table (printed 280): RV58 is RX 145,125 MHz / TX 145,725 MHz.
The Skupina V key's answer (a) reads "TX/RX 145,725/145,125" — correct, matches the
table exactly. No flag needed here; the S4 packet's problem doesn't carry over to S5.
