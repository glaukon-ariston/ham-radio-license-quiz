# P2-0041 — Add balanced and vivid color theme options

## What changed

`quiz/build/build_quiz.py` only (the file named in `files:`), 82 lines added, none removed.

1. **Two new palette variable blocks**, following exactly the four-block shape the existing
   muted palette already used (light default, `@media (prefers-color-scheme:dark)`, explicit
   `[data-theme="dark"]`, explicit `[data-theme="light"]`), each scoped under a
   `:root[data-palette="balanced"]` / `:root[data-palette="vivid"]` attribute selector:
   - **balanced**: indigo accent (`#3D3AA8` light / `#8F8CF0` dark), warm-neutral grays instead
     of the muted palette's cool teal-gray.
   - **vivid**: violet accent (`#5B21B6` light / `#B98CFF` dark), saturated good/bad/warn.
   - `data-palette="muted"` (or the attribute simply absent, e.g. before JS runs) falls through
     to the original `:root` block unchanged — the muted palette's hex values were not touched.
   - All 15 vars each (`--paper`, `--card`, `--ink`, `--muted`, `--line`, `--accent`,
     `--accent-soft`, `--good`, `--bad`, `--good-soft`, `--bad-soft`, `--warn`, `--warn-soft`,
     `--shadow`, `--fx-bg`) are defined for both light and dark in both new palettes.
   - CSS specificity does the composing: `[data-palette="x"]` (1 attribute) beats bare `:root`
     (0 attributes) so a chosen palette always wins over muted; `[data-palette="x"][data-theme=
     "dark"/"light"]` (2 attributes) always beats both the 1-attribute palette rule and the
     1-attribute `[data-theme=...]` muted rule, so an explicit theme override — if one is ever
     wired up — will still win regardless of source order. This means the new palettes compose
     with `prefers-color-scheme` and the (currently-dead) `data-theme` mechanism instead of
     forking a separate code path.

2. **Visible control**: a `<select id="themeSel">` in the sticky header bar (`.barin`), with
   options "Prigušeno" (muted, first/default) / "Uravnoteženo" (balanced) / "Živopisno" (vivid).
   Styled with a new `.themesel` CSS class that only references `var(--card)`, `var(--line)`,
   `var(--accent)` — no hardcoded colors added outside the `:root` blocks.

3. **Persistence**: `localStorage` key `9a-ispit-palette`, read/written by a small block in the
   main `<script>` (mirrors the existing `9a-ispit-v1` progress-store pattern). A second, tiny
   inline `<script>` sits right after `</style>` and before `<header>` — it reads the same key
   and sets `document.documentElement.dataset.palette` synchronously, before the rest of the
   page is parsed, so a saved balanced/vivid choice doesn't flash muted on reload.

## Why these hex values

Picked to keep "vivid" from failing on legibility, per the item's explicit warning. Wrote a
one-off contrast script (WCAG relative-luminance formula, not a library) and ran every
text-bearing pair used in the CSS — `--ink`/`--paper`, `--ink`/`--card`, `--muted`/`--paper`,
`--accent`/`--card`, `--paper`-on-`--accent` (the `.btn.primary` case), `--good`/`--good-soft`
(`.opt.ok .k`), `--bad`/`--bad-soft` (`.opt.no .k`), `--warn`/`--warn-soft` (`.why.check h4`) —
for muted (as a baseline, unchanged), balanced, and vivid, both light and dark.

First-draft vivid-light good/bad/warn came in under 4.5:1 (green `#0E9F52` on its soft
background measured 2.97:1 — a real fail, not just borderline). Darkened `--good`, `--bad`,
`--warn` for vivid-light until each cleared 4.5:1 while staying visibly saturated
(`--good:#087038` → 5.34:1, `--bad:#C11229` → 4.93:1, `--warn:#924300` → 5.82:1). Every other
pair across all three palettes, both modes, was already ≥4.5:1 except muted's pre-existing
good/good-soft at 4.33:1 (unchanged — out of scope, that's the shipped palette).
