# P3-0018 — Book notes, skupina IV tehnički (a)

## Scope

Wrote `quiz/build/notes_book_s4_tehnicki_a.json`: one teaching note per id in
`quiz/build/work/packet_book_s4_tehnicki_a.json` (30 ids, `bk-teh-4-01` through `bk-teh-4-59`,
odd numbers only — this packet was not subject-recut per the item's "Avoid" note, so it spans
every topic at once, drawn from one mock exam paper). Same `{note, formula?, cite}` shape as
the other `notes_book_*` files — no `links` key (matches convention: `link_check.py`/
`check_notes.py` only glob `notes_zzz_expanded_*`, confirmed by running both). `packet_book_
s4_tehnicki_a.json` (also in `files:`) was read only, not edited, even though two of its ids
carry a corrupted/stale live entry — see below.

## Method

1. Rendered/dumped printed RK pages 321–331 with `booktool.py page RK N` and, for every
   question, additionally rendered the page as a PyMuPDF image (not just OCR text) and compared
   every option letter and text against the packet word for word. This is what surfaced both
   defects below — the OCR text dump alone reads the same corrupted text the packet has.
2. Ran a coordinate-level audit of `book_parsed2.json`'s raw `opts` (y,x,text) for all 30 ids,
   reproducing the option-assembly algorithm (`round(y/9)` row-bucket, then sort by x) by hand
   to find any other row-bucket boundary mis-splits like the one found in bk-teh-4-55 — none of
   the other 29 ids showed the failure pattern (all either had exact-tie y-coordinates per row,
   or a small within-row y-jitter that stayed on the same side of a `/9` bucket boundary).
3. For every citation, pulled the actual RK prose page(s) with `booktool.py page`/`find` and
   confirmed the specific claim/number/definition verbatim before writing it into a note — not
   just a topically-plausible chapter. Two exceptions where the book's continuous prose does not
   independently confirm the specific claim (`bk-teh-4-37`, `bk-teh-4-57`) are disclosed as such
   in the note text itself, citing only the exam page, per "cite nothing rather than a plausible
   page."
4. Multi-page citations (e.g. `bk-teh-4-47`'s three separate RK page references) had each page
   individually opened and read, not inferred from one confirmed page in the group.

## Two live defects found, not fixed (out of this item's `files:` to edit as source)

Both are described honestly in the affected note's own text (not glossed over), following the
precedent set by P3-0010's `bk-teh-2-03/13/29` handling — the note describes the verified-real
content and does not quote or affirm the currently-wrong live text.

1. **`bk-teh-4-55`** — the live packet's options **a and b are swapped** relative to the printed
   page (verified by rendering printed str. 331 as an image). Real page: (a) "može prouzročiti
   blokiranje prijamnika", (b) "nikada ne uzrokuje smetnje". Live/packet: a and b holding each
   other's text (c/d are correct). Root cause traced precisely in `book_parsed2.json`'s raw
   `opts` coordinates: the top-row's two options have y-values 103.13 and 104.45 (only 1.32pt
   apart, both really the same printed row) that straddle a `round(y/9)` bucket boundary at
   y=103.5, so the row-bucketing option-assembly algorithm split one printed row into two
   different "rows" and re-sorted them in the wrong order. `book_keys.json` (redak 55, stupac
   IV = `A`) confirms the answer key intends the *real* page's option (a) — "može prouzročiti
   blokiranje prijamnika" — which also matches the book's own prose on receiver blocking (str.
   198, "blokiranja ili smanjivanja osjetljivosti"). The note is written around this verified
   real content; it does not affirm the live "a" text.
2. **`bk-teh-4-47`** — the live packet is **stale** relative to the already-corrected
   `book_parsed2.json`/`book_overrides.json`: the packet still carries options copied from the
   *adjacent* question 48 (RF-envelope modulation percentages), while the real question 47 (and
   the current `book_parsed2.json`) is a figure-only question — four ammeter/voltmeter/Rx wiring
   schematics for indirect resistance measurement, confirmed by rendering str. 329 as an image
   (the four schematics are individually labelled a)-d) in the source itself). Traced the real
   circuit topology by eye at high zoom: schematic (a) has the ammeter in series with the source
   and Rx/voltmeter in parallel with each other (textbook-correct — matches str. 175-176's own
   statement that an ideal ammeter's resistance should be near zero in series and an ideal
   voltmeter's resistance should be as high as possible in parallel); (b) and (c) wrongly put the
   voltmeter in series in the main current loop; (d) puts all three elements in parallel with no
   series element at all. `book_keys.json` (redak 47, stupac IV = `A`) matches schematic (a), the
   only topologically sound one. The note describes this real content and cites the real pages;
   it does not use the packet's currently-attached (wrong) option text.
3. Also (not corrupting, cosmetic): **`bk-teh-4-13`**'s packet `question` field is a stale,
   OCR-garbled leftover (`"Z, — Z=som |"`) while `book_parsed2.json` already carries the
   corrected `"Z0 = 50 Ω; Zizl = 50 Ω; λ/4; Zul = ?"` (confirmed against the rendered page image).
   The note is written from the verified/corrected text. **`bk-teh-4-45`** option (a) has an
   OCR-glued `"S5:1"` where the printed page reads `"5:1"` (confirmed by image) — cosmetic only,
   doesn't change the answer letter; the note uses the real value.
4. **has_figure mislabelled `false`** in the packet for six ids that do have a real figure on the
   page (confirmed by rendering and cross-checked against `book_overrides.json`/
   `figs_book_index.json`, which do carry these): `bk-teh-4-13`, `-15`, `-17`, `-19`, `-43`,
   `-47`. (`bk-teh-4-07` is correctly `true`.) Not fixed — same reasoning as above.

None of these four items are in this item's `files:` to fix (the packet is treated read-only per
the established precedent in P3-0010/P3-0015/P3-0017 even though it is nominally listed); all
four are new findings not previously logged by earlier `book-notes-s*` items (checked the prior
reports for `bk-teh-4-*` mentions — none).
