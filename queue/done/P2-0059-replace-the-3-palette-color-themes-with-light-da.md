# Replace the 3-palette color themes with light, dark, and a waterfall theme

prio:       P2
cluster:    quiz-app-ui
files:      quiz/build/build_quiz.py
blocked-by:

**Why.** P2-0041 gave the quiz three "palettes" (muted/balanced/vivid) each crossed with
light/dark — six CSS variants that share an identical 15-token shape and differ only by hue.
Glaukon calls this "rather pathetic... three very similar look and feels" and wants something
genuinely different instead: a default light theme, a dark theme, and a third theme that is
"vivid, crazy, novel and interesting" — structurally distinct, not just re-hued.

**Done when.** The `data-palette` × `data-theme` grid (`build_quiz.py:27-96`, plus the
`palette`/`PALETTES`/`LS_THEME` JS around `:444-457` and `:493-496`) is replaced by a single
`data-theme="light"|"dark"|"waterfall"` attribute on `<html>` with exactly one flat `:root`
block per theme (no `@media(prefers-color-scheme:dark)` duplication — resolve the initial
value once in the pre-paint script at `:261-267` from a stored choice or
`matchMedia("(prefers-color-scheme: dark)")`, defaulting to light/dark by OS and never
auto-landing on waterfall). Light and Dark reuse the existing "muted" light/dark token values
as-is. Waterfall is a new, self-contained theme themed on an SDR panadapter/waterfall display
— near-black surfaces, a spectrum-gradient accent (violet→cyan→green→amber→red, e.g. via a new
optional `--fx-gradient` token used with a safe fallback), glow-tinted `--shadow`, and clearly
hue-separated good/bad/warn colors — covering every existing token
(`--paper --card --ink --muted --line --accent --accent-soft --good --bad --good-soft
--bad-soft --warn --warn-soft --shadow --fx-bg`). The header `<select id="themeSel">` offers
exactly these three options, the choice persists across reloads under a new `localStorage` key
(`9a-ispit-theme`; best-effort delete the old `9a-ispit-palette` key on load, no value mapping
— the concepts don't correspond 1:1), and the narrow-viewport label map at `:493-496` is
updated to match. Verify: `python quiz/build/rebuild.py` succeeds; opening the built page and
cycling `themeSel` through all three themes renders the header, question card,
selected/correct/incorrect option states, progress meter, and buttons legibly in each; clearing
`localStorage` and toggling OS dark-mode emulation lands on light or dark (never waterfall)
with no flash of the wrong theme; seeding the old `9a-ispit-palette` key and reloading falls
back cleanly instead of erroring; resizing below 480px keeps the narrow theme labels working.

**Avoid.** Don't add a fourth axis or keep the old palette/mode cross — this replaces it, it
doesn't extend it. Don't hardcode colors outside the `:root[data-theme=...]` blocks; every
themed element already reads `var(--*)`, so the new waterfall theme should only need its token
set (plus the couple of small additive rules that consume `--fx-gradient`). Run a WCAG contrast
check (same approach as P2-0041's report) on ink/paper, ink/card, accent/paper,
good/good-soft, bad/bad-soft, warn/warn-soft for all three themes before finalizing hexes —
"crazy" must not come at the cost of legibility, especially for the waterfall theme's
saturated palette. Don't animate the new scanline/glow flourishes — this page is used during
timed practice exams, and motion during a 45-question timer is more likely to distract than
delight; keep any texture static. The existing global `prefers-reduced-motion:reduce` rule
(`build_quiz.py:243`) must still suppress anything added. Don't hand-edit `quiz/quiz.html`
directly — it's regenerated by `rebuild.py` from `build_quiz.py`.
